## 仓库是怎么拆的

可以把整个项目想成一家小餐馆：


| 路径                       | 人话                                        |
| ------------------------ | ----------------------------------------- |
| `my_gpt/`（里面那层 Python 包） | **厨房设备**：模型、数据、存盘、推理。别的脚本都来调用它。           |
| `scripts/`               | **点餐入口**：预训练、蒸馏、对话……你在命令行运行的是这些文件。        |
| `configs/`               | **菜谱参数**：层数、学习率。改数字重跑，尽量少改代码。             |
| `tests/`                 | **试吃**：用假数据检查形状、遮罩有没有漏，不需要真去训练。           |
| `assets/`                | **成品照片**：loss 曲线、生成样例，以后贴进 README。        |
| `notes/`                 | **你的笔记本**：术语、面试、踩坑。                       |
| `requirements.txt`       | **本机购物清单**：写代码、跑测试要用的库。                   |
| `requirements-gpu.txt`   | **云上额外购物清单**：含 vLLM，显卡机器再装。               |
| `.venv/`                 | **隔离的工具箱**：只给这个项目用的 Python 包，避免和系统其它项目打架。 |


两个都叫 `my_gpt` 不奇怪：外面是**项目文件夹**，里面是**同名 Python 包**。写 `import my_gpt` 时，指的是里面那层。

## 依赖相关

- **依赖 / 库 / 包**：别人写好的代码，你 `import` 就能用。`torch` 做张量运算，`transformers` 提供现成 GPT-2 分词器和 Teacher 模型。
- `pip`：安装这些库的命令。
- `requirements.txt`：列出「要装哪些、大概什么版本」。别人克隆仓库后按同一份清单装，环境更接近。
- **虚拟环境 (venv)**：一个项目一个文件夹装着包。激活后，终端里的 `python` / `pip` 才指向这套包。本项目在 `my_gpt/.venv/`。每次新开终端先 `cd` 到 `my_gpt`，再执行 `source .venv/bin/activate`，提示符出现 `(.venv)` 才算成功。
- **CPU 版 / CUDA 版 PyTorch**：同一套 `torch` 有两种安装。CPU 版只能用处理器算，适合本机写代码、跑测试；CUDA 版才能用 NVIDIA 显卡，体积大得多，留给云实例。本机若直接 `pip install torch` 往往会下一整套 CUDA，又用不上。
- **为什么本机不装 vLLM**：vLLM 是高性能推理引擎，安装重、基本按 GPU 设计。你现在在本地写代码、跑 CPU 测试，装它容易失败还占空间。等上云再按 `requirements-gpu.txt` 装。



## 模型结构（后面要手写的零件）

- **Token**：模型不读「汉字/单词」，先把文本切成编号。一句「你好」可能变成几个整数。这串整数叫 token。
- **词表 (vocab)**：编号对照表。GPT-2 大约 50257 个编号。Teacher 和 Student 必须用**同一本词典**，蒸馏才能对上。
- **Tokenizer（分词器）**：文本 ⇄ token 编号。本项目包装 HuggingFace 现成的 GPT-2 分词器，不自己从零训 BPE。
- **Embedding（词嵌入）**：每个编号变成一条长度为 `n_embd` 的向量，例如 512 维。模型真正计算的是这些向量。
- **Decoder-only GPT**：只往「已经出现的字」后面续写，不单独做一个「理解整句再回答」的 Encoder。ChatGPT 类模型也是这一路，只是大很多。
- **层** `n_layer`：同样的积木重复叠几次。6 表示叠 6 块 Transformer。
- **隐藏维度** `n_embd`：向量有多宽。512 比 256 更宽、参数更多、更吃显存。
- **注意力头** `n_head`：一次计算里把「谁该看谁」拆成 8 组小注意力再拼回来。头数变了、总宽度不变时，每头的宽度会变。
- **上下文长度** `block_size` **/ context**：一次最多看多长的 token。256 很短，商品长文以后再说。
- **参数量（约 80M）**：模型里要学习的数字大约八千万个。比网上的 70B 小三个数量级，用来把流程跑通。
- **RoPE**：用旋转的方式告诉模型「字在第几位」，而不是另学一张位置表。和「可学习位置编码」对比是一组消融。
- **RMSNorm**：把向量的大小规范化，训练不容易爆。比 LayerNorm 少几个参数。
- **FFN / MLP**：注意力之后的两层全连接，负责「混合特征」。
- **Causal mask**：禁止看**后面**的字。否则考试时偷看答案，训练 loss 会假好，生成却乱。
- **Logits**：模型对词表里每个编号打的分数。还不是概率。
- **Softmax**：把分数变成加起来为 1 的概率。
- **交叉熵 / CE / loss**：正确答案的概率越低，这个数字越大。训练就是把 loss 压下去。
- **残差 (residual)**：`x = x + 某层(x)`，原路留着，梯度更好走。
- **Pre-Norm**：进注意力/FFN 之前先 RMSNorm。比「算完再 Norm」更稳，现在更常见。
- **lm_head**：最后一层线性，把 `C` 维向量打到词表大小，得到 logits。和 `wte` 不共用权重（untied）。
- **labels / 下一个词**：第 t 个位置的答案是第 t+1 个 token。数据层会把序列错开一位；模型里 CE 要求 `labels` 和 `idx` 形状相同。
- **ignore_index=-100**：这个编号不计入 loss，留给以后的 padding。
- **BOS / EOS**：序列开始/结束的特殊编号。GPT-2 里两者常常都是 `<|endoftext|>`（50256）。
- **PAD**：把短句补齐时用的填充号。GPT-2 没有独立 pad，我们用 eos 顶上。预训练拼长流时可以先不用 pad。
- **PPL（困惑度）**：把平均交叉熵再 `exp` 一下，更常拿来汇报。「越接近 1 越不困惑」，小模型在真实文本上会远大于 1。



## 训练相关

- **预训练**：在大量文本上做「猜下一个 token」，先学会语言模样。
- **继续预训练 (CPT)**：已经有一套权重，再拿到**电商评论**这类领域文本上接着训，让文风更像评论。
- **SFT**：给「问题-回答」对，教模型按对话格式说话。30 天可选。
- **学习率**：每一步改参数改多大。太大易炸，太小学很慢。
- **Weight decay**：让参数不要太大，一种正则。Embedding、Norm、bias 通常不衰减；二维 Linear 权重衰减。
- **AdamW**：PyTorch 自带的优化器。我们只负责**分组参数并调用它**，不手写公式。
- **token 切分**：全文先变成一条编号长河，再按位置切 train/val（我们 90/10）。和「按文档 ID 切」不同，后者更不容易泄漏同一条评论。
- **错开一位**：输入 `x = tokens[i:i+T]`，标签 `y = tokens[i+1:i+T+1]`，每个位置猜下一个编号。
- **Batch**：一次塞多少条样本。越大越稳、越吃显存。
- **Checkpoint**：某一刻的权重快照，存在磁盘上，中断了能接着训，也能拿去生成。
- **过拟合几条样本**：故意只拿很少数据，看 loss 能不能降到接近 0。能降说明代码没写反，不说明模型强。
- **训练循环**：反复「取一批数据 → 算 loss → backward → 裁剪梯度 → opt.step」。
- **梯度裁剪 (grad clip)**：把所有参数梯度的总长度限制在例如 1.0，减轻偶发的梯度爆炸 / NaN。
- **AMP / 混合精度**：部分计算用 16 位小数，加快、省显存。A10/4090 常用 bf16；更老的卡用 fp16 还要 GradScaler。
- **GradScaler**：fp16 数值范围小，先把 loss 放大再反传，更新时再缩回去，避免梯度变成 0。bf16 一般不需要。
- **贪心解码 (greedy)**：每一步都选当前概率最大的那个 token。简单但容易重复；Top-k / Top-p 以后再加。
- **OOM**：显存不够，程序直接挂。解决办法通常是减小 batch 或模型。
- **消融**：一次只改一个开关（例如有没有 RoPE），看曲线差在哪，用来写分析而不是堆功能。



## 压缩与推理（后面 Demo）

- **Teacher / Student**：大老师（现成 gpt2）教小学生（你手写的小 GPT）。
- **蒸馏**：学生既要猜对真实下一个词，也要模仿老师的概率分布。温度 T 会把分布弄得更「平」，更好学。
- **量化 INT8**：用更少的比特存权重，模型变小、CPU 上可能更快，质量可能掉一点。本项目做训练后量化 Demo，不是训练中量化。
- **KV-Cache**：生成第 100 个字时，前 99 个的中间结果存起来，不要每次从头算注意力。
- **Top-k / Top-p**：生成时不要永远选概率最大的那个字（那叫 greedy），从「比较像」的一批里抽样，更自然。
- **DDP**：多张 GPU 各算一部分数据，把梯度加起来再更新。14 天只把代码架子写对。
- **vLLM**：别人做好的高速推理框架。我们最多把权重导出后让它加载，或先跑官方 gpt2 证明「我会用这个工具」。
- **CLIP**：图文一对的现成模型。我们冻住「看图」的一半，用一层线性把图像向量的长度改成和 GPT 一样，接到句子前面。这叫概念验证，不是训练多模态大模型。
- **HuggingFace (HF)**：模型和分词器的常用平台/格式。导出 HF 格式是为了让 vLLM 等工具认。
